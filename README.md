# Fukidashi

Gmail を、LINE のような会話ビューで読むためのローカルツールです。
自分の発言は右、相手は左。**読む専用**で、Gmail 側の状態（既読・ラベル・削除）を
一切書き換えません。

メールは自分のパソコンの中だけで処理されます。外部のサーバーはどこにも存在せず、
パスワードもメール本文も、Gmail 以外には送られません。

## なぜ作ったか

Gmail が読みにくい原因は見た目ではなくデータの持ち方なので、CSS を被せても直りません。
このツールは3点だけを違うやり方でやります。

| Gmail | Fukidashi |
|---|---|
| 件名と `References` でスレッドを組む → 件名を変えられると分裂する | **参加者**で会話をまとめる → 同じ相手なら常に1本 |
| 引用と署名が本文に積み重なる | 引用・返信ヘッダ・署名を剥がして、その回の発言だけを吹き出しにする |
| 新着や操作で並びが変わり、取りこぼす | 時刻順に固定。未読の先頭に「ここから未読」を挟む |
| 人からのメールが通知やメルマガに埋もれる | **「人」と「お知らせ」のタブに分ける** |

### 人とお知らせの振り分け

推測ではなく、順に次の根拠で決めます。

1. **こちらが一度でも返信している** → 無条件で「人」（アドレスが `support@` でも人）
2. `List-Unsubscribe` / `List-Id` / `Precedence: bulk` などの一斉配信ヘッダを持つ → 「お知らせ」
3. 本文に配信停止の導線（「配信停止」「購読解除」`unsubscribe` など）がある → 「お知らせ」
4. 送ってきたアドレスが全て `noreply@` `info@` などの機械アドレス、
   または `mail.` `emagazine.` などの配信用サブドメイン → 「お知らせ」
5. どれにも当たらなければ「人」

## 必要なもの

- Python 3.9 以上（macOS には最初から入っています）
- Gmail アカウントと、そこで作る**アプリパスワード**（2段階認証が必要です）
- Windows / Linux の場合のみ `pip install keyring`

追加のライブラリは要りません。標準ライブラリだけで動きます。

## はじめかた

**パソコンに詳しくない方は [はじめての方へ](docs/はじめての方へ.md) をご覧ください。**
アプリパスワードの作り方から、警告画面の対処まで順を追って書いてあります。

### Mac・Windows（ターミナルを使わない場合）

[Releases](../../releases/latest) から落として展開し、ダブルクリックしてください。
初回はアカウントとアプリパスワードを画面の案内どおりに入れるだけです。

| | ファイル | 初回だけ必要なこと |
|---|---|---|
| Mac | `Fukidashi-macOS.zip` | システム設定 → プライバシーとセキュリティ → **「このまま開く」** |
| Windows | `Fukidashi-Windows.zip` | 警告画面の**「詳細情報」→「実行」** |

どちらも、署名していないアプリに OS が一律で出す警告です。
署名には年間の費用がかかるため、いまは付けていません。

**Mac では必ず「アプリケーション」フォルダへ移してから開いてください。**
ダウンロードした場所のまま開くと macOS が一時領域に写して動かし、その領域が
消えたあと画面が出なくなります。

**Mac で「右クリック → 開く」は使えません。** macOS 15 (Sequoia) から Apple が
その抜け道を廃止したので、システム設定から許可する必要があります。
手順は [はじめての方へ](docs/はじめての方へ.md#fukidashi-は開いていませんと出たら) にあります。
ターミナルが使えるなら `xattr -dr com.apple.quarantine /Applications/Fukidashi.app` でも構いません。

自分でビルドする場合:

```bash
python3 make_app.py --zip                          # macOS
pyinstaller packaging/fukidashi.spec --noconfirm   # Windows
```

タグを打つと GitHub Actions が両方を作って Releases に添付します。

### ターミナルを使う場合

```bash
git clone https://github.com/<あなた>/fukidashi.git
cd fukidashi
python3 setup.py
```

`setup.py` が、アカウントの登録・アプリパスワードの作成と保存・接続確認・
最初の取り込みまで順に案内します。終わったら:

```bash
python3 serve.py
```

ブラウザが開きます。以降は起動しっぱなしで構いません（3分ごとに自動で新着を取り込みます）。

### アプリパスワードについて

<https://myaccount.google.com/apppasswords> で作る16桁のパスワードです。
Google アカウント本体のパスワードではありません。

**これはメールボックスへのフルアクセス権です。** Fukidashi はこれを
OS の保管庫（macOS キーチェーン / Windows 資格情報マネージャー /
freedesktop secret service）に入れ、Gmail の IMAP サーバーにログインする
ときだけ使います。設定ファイルにもコードにも書き出しません。不要になったら
Google の同じページからいつでも失効させられます。

### 手動で設定する場合

```bash
cp config.example.json config.json
```

`accounts` に読みたいメールボックスを書きます。1つでも複数でも構いません。

```json
"accounts": [
  {"email": "you@gmail.com",   "label": "メイン", "aliases": ["you@example.com"]},
  {"email": "other@gmail.com", "label": "仕事",   "aliases": []}
]
```

**`aliases` は重要です。** 別のアドレス宛のメールが転送されて届いている場合、
それをここに入れないと「相手＋自分の別アドレス」の2人グループとして扱われ、
本来1対1の会話がばらばらになります。

パスワードを自分で保存する場合:

```bash
# macOS
security add-generic-password -U -s gmail_line -a you@gmail.com -w   # 対話入力
# Windows
python -c "import keyring,getpass;keyring.set_password('gmail_line','you@gmail.com',getpass.getpass())"
# Linux
secret-tool store --label=gmail_line service gmail_line account you@gmail.com
```

## 使う

```bash
python3 sync.py            # 全アカウントを前回の続きから取り込む
python3 serve.py           # 画面を開く（右上の「同期」ボタンでも取り込めます）
```

| キー | 動作 |
|---|---|
| `/` | 検索へ |
| `↑` `↓` | 会話を移動 |
| `Esc` | 検索を抜ける／一覧へ戻る |
| タブ | 「人」「お知らせ」の切り替え（選んだタブは記憶されます） |

### 複数アカウント

- 会話は**アカウントをまたいで1本にまとまります**。同じ相手なら、どちらの
  アカウント宛に届いたかに関係なく同じトークに並びます。
- **どのアカウントのアドレスも「自分」**です。したがって自分のアカウント同士の
  やりとりは「自分へのメモ」に入ります。
- 同じメールが両方に届いている場合（Cc など）は `Message-ID` で重複を判定して
  **1通だけ**表示します。
- 画面上部のチップで「すべて／各アカウント」を切り替えられます。

## 設定項目

| 項目 | 既定 | 説明 |
|---|---|---|
| `accounts[].email` | — | Gmail アドレス |
| `accounts[].aliases` | `[]` | そのアカウントに届く自分の別アドレス |
| `accounts[].label` | アドレスの左側 | 画面に出す短い名前 |
| `initial_days` | `90` | 初回にさかのぼる日数 |
| `strip_patterns` | `[]` | 本文から消したい定型文（正規表現） |
| `force_people` | `[]` | 必ず「人」に入れる相手（部分一致） |
| `force_notices` | `[]` | 必ず「お知らせ」に入れる相手（部分一致） |
| `mute` | `[]` | どちらのタブにも出さない相手（部分一致） |
| `max_fetch_bytes` | `5000000` | これより大きいメールは本文を取りに行かない |
| `port` | `8765` | ローカルサーバーのポート |
| `db_path` | `data/mail.db` | データの置き場所（絶対パス可） |

### アプリとコマンドの併用

アプリで読みつつ、たまにコマンドで手入れする使い方ができます。
手元に `config.json` が無ければ、コマンドは自動でアプリ側の設定を見ます。

```bash
python3 reprocess.py     # アプリのデータに対して本文を作り直す
python3 sync.py          # アプリのデータに取り込む
```

アプリを起動したままでも構いません（SQLite が同時アクセスを処理します）。
明示したい場合は `GMAIL_LINE_CONFIG` で設定ファイルを指定してください。

| | 設定ファイル |
|---|---|
| macOS | `~/Library/Application Support/Fukidashi/config.json` |
| Windows | `%APPDATA%\Fukidashi\config.json` |
| Linux | `~/.config/fukidashi/config.json` |

### 定型文の削り方

引用剥がしに加えて、次は自動で落とします。

- `-- ` から下の署名
- 〒 / TEL / FAX / E-MAIL が2行以上続く連絡先ブロック（本文の後半にある場合のみ）
- 末尾の飾り罫線（`━━━━` など）

いずれも「本文の半分以上は削らない」条件つきで、削った内容は吹き出しの
「引用を含む全文を表示」からいつでも読めます。

自分の受信箱に固有の定型文は `strip_patterns` に足してください。足したあとは:

```bash
python3 reprocess.py
```

取り込んだ生データを保存してあるので、**再ダウンロードなしで数秒**で作り直します。
Gmail には接続しません。

## 返信

「人」のトークには返信を書けます。吹き出しの下に入力欄が出ます。

宛先と差出人を入力欄の上に必ず表示します。**送信ボタンを押してから8秒間は
取り消せます。** `Enter` は改行で、送信は押す操作（または `⌘/Ctrl + Enter`）
だけにしてあるので、勢いで送ってしまうことがありません。

送ったメールは Gmail の「送信済み」に入り、少しあとの取り込みで自分の
吹き出しとして並びます。

割り切っていること:

- **文字だけです。** 添付も書式も付けられません
- **「お知らせ」のトークには返信できません。** 通知やメルマガへの返信は
  届かないうえ事故のもとなので、入力欄を出しません
- **差出人はアカウントのアドレスになります。** 別アドレス宛に届いたメールへ
  返信すると、Gmail が差出人を書き換えます。その場合は入力欄の上に警告を出します
  （Gmail の「アカウント」設定で別アドレスを登録・確認しておけば回避できます）

## 同時アクセスについて

画面は `ThreadingHTTPServer` が配るので、読み込みは複数スレッドで同時に走ります。
Python の `sqlite3` は `threadsafety=1`、つまり**接続をスレッド間で共有できません**。
`check_same_thread=False` は Python 側の確認を外すだけで、SQLite 自体が安全に
なるわけではなく、共有すると内部構造が壊れて落ちます。

そのため `store.Database` がスレッドごとに接続を持ちます。ファイルは WAL なので、
接続が複数あっても同時に読み書きできます。`tests/test_concurrency.py` で
12スレッドから同時に読み書きして壊れないことを確認しています。

## 受け口の守り

画面は `127.0.0.1` のローカルサーバから配られますが、**それだけでは
守りになりません。** たまたま開いた無関係なウェブページが、このサーバへ
要求を投げられてしまうためです。3つの検査をかけています。

| 検査 | 防ぐもの |
|---|---|
| `Host` が `127.0.0.1` / `localhost` か | **DNS リバインディング。** 攻撃者が自分のドメインを `127.0.0.1` に向けると、ブラウザからは同一オリジンに見え、`Origin` の検査をすり抜けてメールの中身まで読まれる |
| `Origin` が自分自身か | よそのページから同期や終了を勝手に走らせる、ふつうの CSRF |
| 独自ヘッダの合言葉 | 独自ヘッダが付くとブラウザは事前確認を必ず行い、こちらは許可を返さないので、よそのページからの要求はそもそも届かない |

合言葉は起動ごとに作り直し、このサーバが返す画面にだけ埋め込みます。
アプリを起動し直すと変わるため、開きっぱなしの画面は自動で読み込み直します。

## 仕様と割り切り

- **受信箱は書き換えません。** IMAP は `BODY.PEEK` しか使わないので、同期しても
  未読が既読になりません。ラベルも削除も触りません。
- **対象は「すべてのメール」。** 送信済みも含めて1本の会話に並びます。
  ゴミ箱と迷惑メールは Gmail の仕様上ここに入らないので、表示されません。
- **本文中の URL はリンクにしません。** メール本文は信用できない入力なので、
  行き先が隠れないよう全文をそのまま文字として出します。
- **添付ファイルは名前だけ**表示します。中身は取得も保存もしません。
- **大きいメール**（既定 5MB 超）は本文を取りに行かず、その旨を吹き出しに出します。

## データの扱い

すべて SQLite の1ファイルに入ります。消せば取り込み前に戻ります。

| 使い方 | 置き場所 |
|---|---|
| アプリ | `~/Library/Application Support/Fukidashi/mail.db` |
| コマンド | `data/mail.db`（`db_path` で変更可） |

**クラウド同期フォルダ（iCloud / Google ドライブ / Dropbox）に置かないでください。**
理由は2つあります。

1. SQLite は複数の機械から同時に触られることを想定していません。同期の途中に
   書き込みが重なると壊れます。
2. macOS のプライバシー保護により、アプリからこれらのフォルダを読めず
   `authorization denied` で起動できません。

複数の機械で使いたい場合は、**それぞれの機械で取り込んでください。** メールの
正本は Gmail 側にあり、このファイルは手元の写しにすぎないので、同期させる
必要がありません。

**このファイルにはメール本文と受信した生データが、暗号化されずに入っています。**
再解析のために生データを保存しているためで、そのぶんサイズも大きめです
（3ヶ月ぶん・5000通で 150MB 程度）。クラウド同期フォルダや共有パソコンに
置く場合は、そこに全メールのコピーが置かれることを理解しておいてください。
置き場所は `db_path` で変えられます。

## 困ったとき

**アプリが起動しない／すぐ落ちる**
`~/Library/Logs/Fukidashi.log` に理由が残ります。
`authorization denied` と出ている場合は、データの置き場所がクラウド同期
フォルダになっています（上の「データの扱い」を参照）。

**アカウントを足したのに何も出ない**
そのアカウントをまだ同期していません。`python3 sync.py` を実行してください。

**`Invalid credentials` と出る**
アプリパスワードではなく通常のパスワードを入れている可能性があります。
Gmail 側で IMAP が無効になっていないかも確認してください（設定 → メール転送と POP/IMAP）。

**送信済みメールが出てこない**
「すべてのメール」が見つからず INBOX を使った場合に起きます。同期時のログに警告が出ます。

**本文が出ない／文字化けする**
まず `python3 reprocess.py` を試してください。解析側の問題なら再取得なしで直ります。

**引用が剥がれきらない／剥がしすぎる**
`strip_patterns` に追記して `python3 reprocess.py`。
剥がしすぎた場合でも「引用を含む全文を表示」で元の本文を読めます。

**取り込み直したい**

```bash
python3 sync.py --full                              # 全部
python3 sync.py --full --account other@gmail.com    # 1アカウントだけ
```
