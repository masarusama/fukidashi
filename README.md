# Fukidashi

Gmail を、LINE のような会話ビューで読み、返信するためのローカルツールです。
自分の発言は右、相手は左。受信箱の状態（既読・ラベル・削除）は一切書き換えません。

メールは自分のパソコンの中だけで処理されます。外部のサーバーはどこにも存在せず、
パスワードもメール本文も、Gmail 以外には送られません。

**例外が1つだけあります。** あなたが自分で Google の API キーを入れて使う、任意の
「AI で返信案」です（下の同名の節を参照）。使うと、押した会話の直近のやりとりが
Google に送られます。**既定ではオフ**で、キーを入れない限り、何も送られません。

## なぜ作ったか

Gmail が読みにくい原因は見た目ではなくデータの持ち方なので、CSS を被せても直りません。
このツールは3点だけを違うやり方でやります。

| Gmail | Fukidashi |
|---|---|
| 件名と `References` でスレッドを組む → 件名を変えられると分裂する | **参加者**で会話をまとめる → 同じ相手なら常に1本 |
| 引用と署名が本文に積み重なる | 引用・返信ヘッダ・署名を剥がして、その回の発言だけを吹き出しにする |
| 新着や操作で並びが変わり、取りこぼす | 時刻順に固定。未読の先頭に「ここから未読」を挟む |
| 人からのメールが通知やメルマガに埋もれる | **「人」と「お知らせ」のタブに分ける** |

### 人とお知らせの振り分け

推測ではなく、順に次の根拠で決めます。

1. **こちらが一度でも返信している** → 無条件で「人」（アドレスが `support@` でも人）
2. `List-Unsubscribe` / `List-Id` / `Precedence: bulk` などの一斉配信ヘッダを持つ → 「お知らせ」
3. 本文に配信停止の導線（「配信停止」「購読解除」`unsubscribe` など）がある → 「お知らせ」
4. 送ってきたアドレスが全て `noreply@` `info@` などの機械アドレス、
   または `mail.` `emagazine.` などの配信用サブドメイン → 「お知らせ」
5. どれにも当たらなければ「人」

## 似たもの

同じ発想のものは、すでにあります。選ぶ前に知っておいてください。調べたのは 2026-10-04
で、**どれも実際には試していません**（公式ページや README の記述にもとづきます）。

| | 内容 | Fukidashi との違い |
|---|---|---|
| [Spike](https://www.spikenow.com/) | 件名ではなく人ごとにまとめる、チャット風のメールアプリ（商用）。PC・スマホ・ブラウザで使える | 同社のサーバーを経由し、暗号化して保管する、と説明されている。有料プランがある（料金は公式で）。ターミナル不要でサポートもあるので、「預けてよい」人にはこちらが楽 |
| [Parula](https://github.com/mustang-im/mustang)（OSS） | Thunderbird の開発者による、メール・チャット・カレンダーの統合クライアント。データはローカルだけ。メールの表示の1つに「チャット表示」がある | 大きな統合アプリ。チャット表示がどこまでのものかは確認していない |
| [Gmail-chat-view-whatsapp-style](https://github.com/Lalitha-balijepalli/Gmail-chat-view-whatsapp-style)（OSS） | Gmail を送信者ごとにまとめ、WhatsApp 風の吹き出しで見せる Web アプリ。AI の要約つき | 個人の小さなプロジェクト（★0）。品質は確認していない |
| [Axichat](https://github.com/axichat/axichat)（OSS） | メールのスレッドをチャットにする。メールと XMPP チャットとカレンダーを一つにしたアプリ | 目的が違う。開発中と明記されている |
| [Delta Chat](https://delta.chat/)（OSS） | メールを土台にした、チャットアプリ | 私の理解では、既存の受信箱を読みやすくするものではなく、メールを運び屋にして新しくチャットするもの |

過去には MailTime など、LINE 風のメールアプリもありましたが、今も使えるかは確認していません。

**Fukidashi を選ぶ理由があるとすれば、次の3つです。**

- **メールを第三者のサーバーに置かない。** IMAP で Gmail に直接つなぎ、メールはこのパソコンの中だけにあります
  （任意の「AI で返信案」を使うときを除く）
- **日本語メールに合わせて直せる。** 〒・TEL の署名、「2026年1月5日(月) …:」形式の引用、ISO-2022-JP、
  配信停止の文言による「人」と「お知らせ」の振り分けなど。**ただし、他のアプリがこれらをどこまで
  扱えるかは確認していません**
- **小さくて、自分で読んで直せる。** 標準ライブラリだけで動き、追加の依存がありません

**逆に、向かない人もいます。** ターミナルや警告画面が苦手な人、サポートがほしい人、スマホ単体で
使いたい人（Fukidashi のスマホ表示は、パソコンが起きている間だけです）、外出先から見たい人、
添付ファイルを扱いたい人（添付は名前の表示だけで、送ることもできません）は、Spike のような
アプリのほうが合います。

## 必要なもの

- Python 3.9 以上（macOS には最初から入っています）
- Gmail アカウントと、そこで作る**アプリパスワード**（2段階認証が必要です）
- Windows / Linux の場合のみ `pip install keyring`

追加のライブラリは要りません。標準ライブラリだけで動きます。

## はじめかた

**パソコンに詳しくない方は [はじめての方へ](docs/はじめての方へ.md) をご覧ください。**
アプリパスワードの作り方から、警告画面の対処まで順を追って書いてあります。

### Mac・Windows（ターミナルを使わない場合）

[Releases](../../releases/latest) から落として展開し、ダブルクリックしてください。
初回はアカウントとアプリパスワードを画面の案内どおりに入れるだけです。

| | ファイル | 初回だけ必要なこと |
|---|---|---|
| Mac | `Fukidashi-macOS.zip` | システム設定 → プライバシーとセキュリティ → **「このまま開く」** |
| Windows | `Fukidashi-Windows.zip` | 警告画面の**「詳細情報」→「実行」** |

どちらも、署名していないアプリに OS が一律で出す警告です。
署名には年間の費用がかかるため、いまは付けていません。

**Mac では必ず「アプリケーション」フォルダへ移してから開いてください。**
ダウンロードした場所のまま開くと macOS が一時領域に写して動かし、その領域が
消えたあと画面が出なくなります。

**Mac で「右クリック → 開く」は使えません。** macOS 15 (Sequoia) から Apple が
その抜け道を廃止したので、システム設定から許可する必要があります。
手順は [はじめての方へ](docs/はじめての方へ.md#fukidashi-は開いていませんと出たら) にあります。
ターミナルが使えるなら `xattr -dr com.apple.quarantine /Applications/Fukidashi.app` でも構いません。

自分でビルドする場合:

```bash
python3 make_app.py --zip                          # macOS
pyinstaller packaging/fukidashi.spec --noconfirm   # Windows
```

タグを打つと GitHub Actions が両方を作って Releases に添付します。

### ターミナルを使う場合

```bash
git clone https://github.com/<あなた>/fukidashi.git
cd fukidashi
python3 setup.py
```

`setup.py` が、アカウントの登録・アプリパスワードの作成と保存・接続確認・
最初の取り込みまで順に案内します。終わったら:

```bash
python3 serve.py
```

ブラウザが開きます。以降は起動しっぱなしで構いません（3分ごとに自動で新着を取り込みます）。

### アプリパスワードについて

<https://myaccount.google.com/apppasswords> で作る16桁のパスワードです。
Google アカウント本体のパスワードではありません。

**これはメールボックスへのフルアクセス権です。** Fukidashi はこれを
OS の保管庫（macOS キーチェーン / Windows 資格情報マネージャー /
freedesktop secret service）に入れ、Gmail の IMAP サーバーにログインする
ときだけ使います。設定ファイルにもコードにも書き出しません。不要になったら
Google の同じページからいつでも失効させられます。

### 手動で設定する場合

```bash
cp config.example.json config.json
```

`accounts` に読みたいメールボックスを書きます。1つでも複数でも構いません。

```json
"accounts": [
  {"email": "you@gmail.com",   "label": "メイン", "aliases": ["you@example.com"]},
  {"email": "other@gmail.com", "label": "仕事",   "aliases": []}
]
```

**`aliases` は重要です。** 別のアドレス宛のメールが転送されて届いている場合、
それをここに入れないと「相手＋自分の別アドレス」の2人グループとして扱われ、
本来1対1の会話がばらばらになります。

パスワードを自分で保存する場合:

```bash
# macOS
security add-generic-password -U -s gmail_line -a you@gmail.com -w   # 対話入力
# Windows
python -c "import keyring,getpass;keyring.set_password('gmail_line','you@gmail.com',getpass.getpass())"
# Linux
secret-tool store --label=gmail_line service gmail_line account you@gmail.com
```

## 使う

```bash
python3 sync.py            # 全アカウントを前回の続きから取り込む
python3 serve.py           # 画面を開く（右上の「同期」ボタンでも取り込めます）
```

| キー | 動作 |
|---|---|
| `/` | 検索へ |
| `↑` `↓` | 会話を移動 |
| `Esc` | 検索を抜ける／一覧へ戻る |
| タブ | 「人」「お知らせ」の切り替え（選んだタブは記憶されます） |

### 複数アカウント

- 会話は**アカウントをまたいで1本にまとまります**。同じ相手なら、どちらの
  アカウント宛に届いたかに関係なく同じトークに並びます。
- **どのアカウントのアドレスも「自分」**です。したがって自分のアカウント同士の
  やりとりは「自分へのメモ」に入ります。
- 同じメールが両方に届いている場合（Cc など）は `Message-ID` で重複を判定して
  **1通だけ**表示します。
- 画面上部のチップで「すべて／各アカウント」を切り替えられます。

## 設定項目

| 項目 | 既定 | 説明 |
|---|---|---|
| `accounts[].email` | — | Gmail アドレス |
| `accounts[].aliases` | `[]` | そのアカウントに届く自分の別アドレス |
| `accounts[].label` | アドレスの左側 | 画面に出す短い名前 |
| `initial_days` | `90` | 初回にさかのぼる日数 |
| `strip_patterns` | `[]` | 本文から消したい定型文（正規表現） |
| `force_people` | `[]` | 必ず「人」に入れる相手（部分一致） |
| `force_notices` | `[]` | 必ず「お知らせ」に入れる相手（部分一致） |
| `mute` | `[]` | どちらのタブにも出さない相手（部分一致） |
| `max_fetch_bytes` | `5000000` | これより大きいメールは本文を取りに行かない |
| `mobile_always_on` | `false` | `true` にすると、起動のたびにスマホ用の待ち受けを自動で開き、ペアリングしたスマホを90日覚える。`mobile_ip` が必須 |
| `mobile_ip` | （空） | スマホ用の待ち受けアドレス。空なら Wi-Fi のアドレスを自動で選ぶ。外出先から読むなら Tailscale のアドレス（`100.x.x.x`） |
| `ai_model` | （空） | 「AI で返信案」で最初に使うモデル。空なら `gemini-3.5-flash` から |
| `port` | `8765` | ローカルサーバーのポート |
| `db_path` | `data/mail.db` | データの置き場所（絶対パス可） |

### アプリとコマンドの併用

アプリで読みつつ、たまにコマンドで手入れする使い方ができます。
手元に `config.json` が無ければ、コマンドは自動でアプリ側の設定を見ます。

```bash
python3 reprocess.py     # アプリのデータに対して本文を作り直す
python3 sync.py          # アプリのデータに取り込む
```

アプリを起動したままでも構いません（SQLite が同時アクセスを処理します）。
明示したい場合は `GMAIL_LINE_CONFIG` で設定ファイルを指定してください。

| | 設定ファイル |
|---|---|
| macOS | `~/Library/Application Support/Fukidashi/config.json` |
| Windows | `%APPDATA%\Fukidashi\config.json` |
| Linux | `~/.config/fukidashi/config.json` |

### 定型文の削り方

引用剥がしに加えて、次は自動で落とします。

- `-- ` から下の署名
- 〒 / TEL / FAX / E-MAIL が2行以上続く連絡先ブロック（本文の後半にある場合のみ）
- 末尾の飾り罫線（`━━━━` など）

いずれも「本文の半分以上は削らない」条件つきで、削った内容は吹き出しの
「引用を含む全文を表示」からいつでも読めます。

自分の受信箱に固有の定型文は `strip_patterns` に足してください。足したあとは:

```bash
python3 reprocess.py
```

取り込んだ生データを保存してあるので、**再ダウンロードなしで数秒**で作り直します。
Gmail には接続しません。

## 返信

「人」のトークには返信を書けます。吹き出しの下に入力欄が出ます。

宛先と差出人を入力欄の上に必ず表示します。**送信ボタンを押してから8秒間は
取り消せます。** `Enter` は改行で、送信は押す操作（または `⌘/Ctrl + Enter`）
だけにしてあるので、勢いで送ってしまうことがありません。

送ったメールは Gmail の「送信済み」に入り、少しあとの取り込みで自分の
吹き出しとして並びます。

割り切っていること:

- **文字だけです。** 添付も書式も付けられません
- **「お知らせ」のトークには返信できません。** 通知やメルマガへの返信は
  届かないうえ事故のもとなので、入力欄を出しません
- **差出人はアカウントのアドレスになります。** 別アドレス宛に届いたメールへ
  返信すると、Gmail が差出人を書き換えます。その場合は入力欄の上に警告を出します
  （Gmail の「アカウント」設定で別アドレスを登録・確認しておけば回避できます）

## 同時アクセスについて

画面は `ThreadingHTTPServer` が配るので、読み込みは複数スレッドで同時に走ります。
Python の `sqlite3` は `threadsafety=1`、つまり**接続をスレッド間で共有できません**。
`check_same_thread=False` は Python 側の確認を外すだけで、SQLite 自体が安全に
なるわけではなく、共有すると内部構造が壊れて落ちます。

そのため `store.Database` は接続を**1本だけ**持ち、ロックで順番に使います。
問い合わせの結果はロックの中で全部読み切ってから返します（カーソルを外へ
持ち出すと、結局その先で同時に触ることになるため）。

接続をスレッドごとに分ける手もありますが、ここでは誤りです。
`ThreadingHTTPServer` はリクエストごとにスレッドを作るので、接続が
際限なく増えて「Too many open files」で動かなくなります。
`tests/test_concurrency.py` は、壊れないことに加えて**接続が増えていない
こと**も確かめます。

## AI で返信案（任意・既定ではオフ）

返信を書くとき、Google の Gemini に下書きを作ってもらえます。案は**入力欄に入れるだけ**で、
自動では送りません。そのあとは今までどおり、読んで直して送信し、8秒の取り消しも効きます。

使うには、Google AI Studio で作った API キーを入れます。画面の右上の **「AI」** を押して、
キーを貼り付けて保存してください（OS の保管庫に入ります。画面には再表示しません）。
環境変数 `GEMINI_API_KEY` でも渡せます。キーを入れると、「人」の会話を開いたときに、
入力欄の上に「AI で返信案」が現れます。「指示（任意）」に「断る方向で」のように一言書けます。
「もう一案」で、違う書き方の案も出せます。

### 何が Google に送られるか

押した会話の**直近10通**の本文だけです。

| 送る | 送らない |
|---|---|
| 引用・署名を取り除いた本文（1通 2000 字まで） | 引用の中身、添付、メールアドレス、相手の表示名 |
| 発言者が「自分」か「相手」か、日時 | ほかの会話、10通より前のやりとり |
| 件名、あなたが書いた指示 | 「お知らせ」のトーク、自分へのメモ（そもそも使えません） |

何を送るかは、**画面ではなくサーバーが、自分でデータベースから決めます**。画面から文章を
渡す経路は無いので、画面を細工されても、ほかの会話は送れません。

### 無料枠について（大事です）

Google の規約（Gemini API Additional Terms of Service、2026-04-28 更新の版を確認）では、
無料枠は次の扱いです。

- 送った内容と生成された返事は、**Google の製品の改善に使われる**
- **人間のレビュアーが、入力と出力を読むことがある**
- 「無料枠に、機密情報・個人情報を送らないこと」

メールの相手の氏名や事情は、個人情報にあたります。**相手の個人情報が含まれる会話、医療・法務・
お金の話には使わないでください。** 課金を有効にした API キーでは、「製品の改善には使わない」
扱いに変わります（規約は変わるので、最新のものを確認してください）。

そのため、次のようにしています。

- **会話ごとに、初めて使うときに確認します。** 確認の画面にも、上の注意をそのまま出します
- あとから **「この会話では使わない」** にできます。その会話では、サーバーが送りません
- 押したときだけ送ります。自動では送りません
- キーの保存・削除は、**パソコンの中の画面からだけ**です。スマホからはできません
- 本文に「これまでの指示を無視して…」のような文が紛れていても従わないよう、メールの
  本文は「信用できない第三者の文章」として区切って渡します。AI には、ツールも送信の権限も
  渡しません。出てくるのは、入力欄に入る文章だけです

### モデルと上限

先に `gemini-3.5-flash` を使い、404（無い）や429（上限）のときは `gemini-3.5-flash-lite` に
替えます。最初に使うモデルは、設定の `ai_model` で変えられます。無料枠の上限は
Google AI Studio の画面で確認してください（ドキュメントには数値が載っていません）。

### 動作確認の範囲

**本物の Gemini API でも、作者の環境で動くことを確認しました。** 確認できているのは作者の
環境1つだけです。リクエストとレスポンスの形は公式のリファレンス（`models.generateContent`）に
合わせてあり、手元に立てた偽のサーバで、実際の通信の形（宛先・ヘッダ・本文・キーが URL に載らない
こと）と画面の操作も、テストで確かめています。うまくいかない場合は [Issues](../../issues) へ。

## スマホで見る

同じ Wi-Fi にいるスマホで、パソコンの Fukidashi を開けます。読む・返信するができます。
スマホ側にアプリを入れる必要はなく、ブラウザで開きます。

1. パソコンの画面の右上で「スマホ」を押す
2. 説明を読んで「有効にする」を押す
3. 出てきた QR コードを、スマホのカメラで読み取る

これだけです。QR コードを読み取った端末だけが入れます。

**初めに知っておいてほしいこと**

- **通信は暗号化されません（http）。** 同じ Wi-Fi にいる人は、原理的にはメールの中身を
  見られます。**自宅など、信頼できる Wi-Fi でだけ**使ってください。カフェや職場の共有
  Wi-Fi では使わないでください。
- **パソコンが起きていて、スマホが同じ Wi-Fi にいるときだけ**見られます。外出先からは見られません。
- 押したときだけ開き、**Fukidashi を閉じると自動で止まります**。次に使うときは、また
  QR コードを読み取ります（接続の記録は保存しません。「常時オン」にした場合だけ、90日間覚えます。
  下の「外出先から読む」を参照）。
- 初回は、パソコンがファイアウォールの許可を求めることがあります。「許可」を選んでください。
- スマホからは、**終了やスマホ設定の操作はできません**（パソコンの画面からだけです）。

**仕組み（守り）**

画面の HTML には合言葉が埋め込まれているので、LAN 側を素直に開くと、同じ Wi-Fi の誰でも
それを取れてしまいます。そこで次のようにしています。

| | |
|---|---|
| 待ち受けの開き方 | 家庭や職場の内側のアドレス（プライベート IP）にだけ開く。インターネットから直接見えるアドレスでは開かない |
| QR コード | 1回しか使えず、5分で切れる。間違った合言葉が5回続くと、有効なものを全部捨てる |
| 鍵 | QR を読み取った端末に、専用の鍵（Cookie）を渡す。JavaScript から読めず、よそのサイトからの要求には付かない |
| 鍵が無い端末 | 画面も、合言葉も、メールの一覧も一切渡さない |
| アドレスの確認 | 別の名前で来た要求（DNS リバインディング）や、別のサイトからの要求は断る |
| 管理の操作 | 終了・スマホ設定は、LAN 側からは存在しないも同然（404） |

`tests/test_mobile.py` が、実際に待ち受けを立てて、これらを攻撃も混ぜて確かめます。

**動作確認の範囲:** スマホの実機ではまだ確かめていません。スマホと同じ幅（375×812）に
したブラウザで、このパソコンの LAN のアドレスへ QR の URL から入る流れ、戻る操作、返信欄の
表示を確認しています。QR コードは macOS の検出器で、バージョン 1〜10・全マスクのすべてが
読み取れることを確認しています。うまくいかない場合は [Issues](../../issues) へ。

## 外出先から読む（Tailscale）

スマホ表示は、同じ Wi-Fi の中でだけ開きます。外出先から読みたいときは、[Tailscale](https://tailscale.com/)
を使います。端末どうしを、ネットの上で直接つなぐ仕組み（VPN の一種）です。公式の説明では、
通信は WireGuard で暗号化され、個人向けは無料（6ユーザーまで、デバイスは無制限）です。

Tailscale が各端末に渡すアドレスは `100.64.0.0/10` の範囲で、家の Wi-Fi（`192.168.x.x`）とは
**別のネットワーク**です。場所が変わっても、アドレスは変わらない、とされています。

1. パソコンとスマホの両方に Tailscale を入れ、**同じアカウント**でログインする
2. Tailscale のアプリで、パソコンの Tailscale アドレス（`100.x.x.x`）を調べる
3. 設定ファイルに `"mobile_ip": "100.x.x.x"` を書いて、Fukidashi を開き直す
   （Mac のアプリは `~/Library/Application Support/Fukidashi/config.json`）
4. パソコンで「スマホ」→「有効にする」。**Tailscale をつないだスマホで**、QR コードを読み取る

以降は、外出先でも、同じ手順で読めます。

### ブックマークして使う（常時オン）

毎回 QR コードを読み取るのは面倒です。設定に `"mobile_always_on": true` を足すと、次のように
変わります（`mobile_ip` も必要です）。

```json
"mobile_ip": "100.x.x.x",
"mobile_always_on": true
```

- Fukidashi を開くたびに、**待ち受けが自動で開きます。** Tailscale がまだ上がっていないときは、
  開けるまで20秒ごとに試し続けます
- ペアリングしたスマホを、**90日間覚えます。** Fukidashi やパソコンを再起動しても残ります
- スマホで、シートに出る **「ブックマーク用のアドレス」**（`http://100.x.x.x:8765/`）を
  ブックマークします。以降は QR コード無しで開けます。QR コードを読み取れないときは、
  シートの「初めて開くときのアドレス」をコピーして、スマホに送って開けば入れます
- 覚えるのは鍵（Cookie）の中身ではなく、**そのハッシュだけ**です
- スマホをなくしたときは、パソコンの「スマホ」から、**一覧の「切る」**（または「すべての接続を切る」）
- 「無効にする」は**一時停止**になります。「再開する」を押すまで、勝手に開き直しません

**合言葉を入れた固定の URL は、作っていません。** URL は、履歴・同期・画面共有・スクリーン
ショットから漏れやすく、漏れたら90日間、誰でも入れるからです。かわりに、一度ペアリングした端末を
覚える形にしました。鍵は Cookie に入り、URL には出ません。

**代わりに引き受けること:** ペアリングしたスマホは、90日間、パスワード無しでメールを読めます。
**スマホに画面ロックを必ずかけてください。** また、Tailscale のアカウントを他の人と共有している
場合、その人の端末もこのアドレスに届きます（鍵が無ければ入れませんが、前提を知っておいてください）。

macOS で、パソコンの再起動後も自動で使いたいときは、システム設定の「ログイン項目」に
Fukidashi を追加してください。

- 待ち受けは、**設定したアドレスにだけ**開きます（`0.0.0.0` のような全開はしません）
- アドレスは QR の URL か、IP のまま開いてください。**名前（MagicDNS）では開けません**
  （別の名前で来た要求を、守りのために断るためです）
- Tailscale が止まっていると、「設定した mobile_ip は、いまこのパソコンに付いていません」と案内して、開きません
- **パソコンが起きていないと、見られません。** スリープしない設定にしてください
- Fukidashi の通信は http のままですが、Tailscale の暗号化された通信路の中を通ります。
  Tailscale のアドレスでない値を書いた場合は、暗号化されません（画面にもそう出ます）

**動作確認の範囲:** 作者の Mac で、Tailscale の実際のアドレスに、待ち受けが自動で開くこと
（常時オン）、鍵が無い端末は入れないこと、Host を偽る要求を断ることを確認しています。
**Android（Chrome）から、Tailscale 経由でこの Mac に届き、鍵が無い端末には案内の画面だけが返ることを、実機で確認しました。** ペアリングして会話を読む流れは、まだ確認していません。常時オンの経路は、
`tests/test_always_on.py`（54件）が、再起動をまたぐ記憶・90日の期限・1台ずつ切る・一時停止を
確かめています。うまくいかない場合は [Issues](../../issues) へ。

## 受け口の守り

画面は `127.0.0.1` のローカルサーバから配られますが、**それだけでは
守りになりません。** たまたま開いた無関係なウェブページが、このサーバへ
要求を投げられてしまうためです。3つの検査をかけています。

| 検査 | 防ぐもの |
|---|---|
| `Host` が `127.0.0.1` / `localhost` か | **DNS リバインディング。** 攻撃者が自分のドメインを `127.0.0.1` に向けると、ブラウザからは同一オリジンに見え、`Origin` の検査をすり抜けてメールの中身まで読まれる |
| `Origin` が自分自身か | よそのページから同期や終了を勝手に走らせる、ふつうの CSRF |
| 独自ヘッダの合言葉 | 独自ヘッダが付くとブラウザは事前確認を必ず行い、こちらは許可を返さないので、よそのページからの要求はそもそも届かない |

合言葉は起動ごとに作り直し、このサーバが返す画面にだけ埋め込みます。
アプリを起動し直すと変わるため、開きっぱなしの画面は自動で読み込み直します。

## 仕様と割り切り

- **受信箱は書き換えません。** IMAP は `BODY.PEEK` しか使わないので、同期しても
  未読が既読になりません。ラベルも削除も触りません。
- **対象は「すべてのメール」。** 送信済みも含めて1本の会話に並びます。
  ゴミ箱と迷惑メールは Gmail の仕様上ここに入らないので、表示されません。
- **本文中の URL はリンクにしません。** メール本文は信用できない入力なので、
  行き先が隠れないよう全文をそのまま文字として出します。
- **添付ファイルは名前だけ**表示します。中身は取得も保存もしません。
- **大きいメール**（既定 5MB 超）は本文を取りに行かず、その旨を吹き出しに出します。

## データの扱い

すべて SQLite の1ファイルに入ります。消せば取り込み前に戻ります。

| 使い方 | 置き場所 |
|---|---|
| アプリ | `~/Library/Application Support/Fukidashi/mail.db` |
| コマンド | `data/mail.db`（`db_path` で変更可） |

**クラウド同期フォルダ（iCloud / Google ドライブ / Dropbox）に置かないでください。**
理由は2つあります。

1. SQLite は複数の機械から同時に触られることを想定していません。同期の途中に
   書き込みが重なると壊れます。
2. macOS のプライバシー保護により、アプリからこれらのフォルダを読めず
   `authorization denied` で起動できません。

複数の機械で使いたい場合は、**それぞれの機械で取り込んでください。** メールの
正本は Gmail 側にあり、このファイルは手元の写しにすぎないので、同期させる
必要がありません。

**このファイルにはメール本文と受信した生データが、暗号化されずに入っています。**
再解析のために生データを保存しているためで、そのぶんサイズも大きめです
（3ヶ月ぶん・5000通で 150MB 程度）。クラウド同期フォルダや共有パソコンに
置く場合は、そこに全メールのコピーが置かれることを理解しておいてください。
置き場所は `db_path` で変えられます。

## 困ったとき

**アプリが起動しない／すぐ落ちる**
記録に理由が残ります。Windows は `%APPDATA%\Fukidashi\Fukidashi.log`、
Mac は `~/Library/Logs/Fukidashi.log` です。
`authorization denied` と出ている場合は、データの置き場所がクラウド同期
フォルダになっています（上の「データの扱い」を参照）。

**アカウントを足したのに何も出ない**
そのアカウントをまだ同期していません。`python3 sync.py` を実行してください。

**`Invalid credentials` と出る**
アプリパスワードではなく通常のパスワードを入れている可能性があります。
Gmail 側で IMAP が無効になっていないかも確認してください（設定 → メール転送と POP/IMAP）。

**送信済みメールが出てこない**
「すべてのメール」が見つからず INBOX を使った場合に起きます。同期時のログに警告が出ます。

**本文が出ない／文字化けする**
まず `python3 reprocess.py` を試してください。解析側の問題なら再取得なしで直ります。

**引用が剥がれきらない／剥がしすぎる**
`strip_patterns` に追記して `python3 reprocess.py`。
剥がしすぎた場合でも「引用を含む全文を表示」で元の本文を読めます。

**取り込み直したい**

```bash
python3 sync.py --full                              # 全部
python3 sync.py --full --account other@gmail.com    # 1アカウントだけ
```
